# resmigrate — 分辨率热更新迁移模拟器

纯 Go 标准库（无第三方依赖）的确定性模拟：立体渲染 rig 在运行中热更新分辨率时，
历史样本经坐标重映射迁移到新尺寸，采样预算按新像素数重新规划，并对三种迁移策略、
故障注入、回滚与重试做计量对比。

## 运行

```bash
cd resmigrate
go test ./...
go run . --out ../artifacts/resmigrate-go
```

输出目录生成 `report.json`（完整逐帧数据）与 `report.md`（人读报告）。重复运行结果
逐字节一致（确定性 LCG、无随机时间/网络依赖）。

## 三种迁移策略

- `inplace` 原地重建：每只眼保留旧历史、分配新历史并双线性重映射，成功后释放旧缓冲；
  单眼顺序切换，故障时用保存的旧缓冲逆向恢复。
- `doublebuf` 双缓冲切换：新配置在阴影缓冲中完整构建，旧配置持续可呈现；提交是双眼
  指针交换事务，要么两眼一起切换，要么丢弃阴影缓冲、旧配置保持在线。
- `staged` 分阶段迁移：按 6 个水平带逐带构建阴影切片，两眼同带都就绪才提交，旧历史
  逐带释放；峰值内存最低、工时摊到多帧，但接缝处会产生轻微历史失效与连续跳变。

## 记录的指标

- 尺寸轨迹：每个呈现帧与迁移事件的左右眼尺寸、已提交配置、迁移比例与双眼一致性。
- 历史失效比例：重映射后因覆盖不足或分带接缝被清零的目标纹素占比；另含清空重建
  （不重映射）对照行，失效比例恒为 1。
- 峰值内存：模拟 RGBA 历史 32 B/px、线性帧缓冲 24 B/px 的分配/释放计量，含历史类别
  峰值、总峰值及其相对基线/目标稳态的倍率。
- 画面跳变：在固定 160x90 UV 网格上比较相邻呈现帧亮度平均绝对差，跨分辨率可直接比较；
  事件阈值 0.015，仅统计升级窗口起。
- 帧超时：确定性工时模型（采样 + 4-tap 重映射，150000 单位/ms，预算 16.7 ms）。
- 采样预算：固定 SPP（预算随像素增长）与固定总预算（SPP 随分辨率收缩）两种模式。

## 压力场景与安全不变量

场景覆盖尺寸突变（4x、36x 像素）、一眼首试失败后回滚、失败后重试成功、分阶段中途
失败回滚。每个场景校验八项不变量，关键保证：

- 任何已呈现帧的左右眼尺寸必须一致，半迁移状态绝不呈现。
- 新尺寸必须对历史做重映射（清空对照除外）。
- 故障后要么回滚到旧配置、要么重试升级到新配置；失败不得留下永久单眼尺寸不一致。
- 终态尺寸必须等于已提交配置，峰值内存有记录，采样预算随迁移正确规划。
