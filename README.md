# 直通相机前景球体合成

纯 Go 标准库实现的 AR 直通合成样例：程序生成一个带纹理的前景球体，根据真实背景参考深度判断可见性，再与三档曝光直通帧和半透明系统层合成。可执行文件和测试均不依赖第三方包、CGO 或图形库。

## 运行

```bash
go run . -out out
go test ./...
```

常用参数：

```text
-width 640       输出宽度
-height 360      输出高度
-frames 8        延迟统计使用的帧数
-seed 20261125   场景随机种子
-out out         输出目录
-budget 16.667ms 每帧处理延迟预算
```

默认运行会生成：

| 文件 | 内容 |
| --- | --- |
| `out/passthrough.png` | 多曝光融合、色调映射后的直通画面 |
| `out/virtual.png` | 球体虚拟层，透明处表示背景、遮挡或无效深度 |
| `out/composite.png` | 直通 + 深度可见球体 + 半透明系统层 |
| `out/confidence.png` | 灰度置信度图，黑为不可信或无效 |
| `out/depth.png` | 诊断深度图，亮近暗远，黑色为无效深度 |
| `out/metrics.json` | 延迟、深度、曝光、色彩和对齐语义 |

## 深度从哪里来

深度不是从亮度、视差猜测的，也不由球体反推。运行时输入是**与彩色相机已对齐的参考深度**：

```go
DepthM     []float64 // 米，和直通图像逐像素对齐
DepthValid []bool    // 传感器/重建给出的有效性
```

演示程序用解析场景几何生成这份输入，包括后墙、地面和真实前景立柱；它仍然作为外部深度输入进入 `CaptureBundle`，合成代码不读取彩色图来推断深度。接入真实设备时，只需用深度 SDK 或空间重建结果填充这两个切片。

可见性规则是保守的：

```text
valid && virtualDepth < backgroundDepth - 0.012m
```

只有这条规则成立，球体 alpha 才大于 0。真实立柱更近时球体被遮挡；`DepthValid == false` 时不会把虚拟物体强行画到最前，而是保持透明并令置信度为 0。虚拟图统计会分别报告可见、被真实几何遮挡和无效深度像素数。

## 曝光与色彩

程序生成三张不同曝光的直通 LDR 帧，曝光倍率为 `0.125x`、`1x`、`6x`。融合前先做 sRGB 解码，在线性光空间按“接近中间调、未剪裁、未压黑”的权重恢复辐照度，因此高光剪裁帧不会污染结果。

曝光偏差在**所有曝光都可用**的公共像素集上测量，并以 `1x` 附近帧为参考：

```text
deviation_ev = log2(reconstructedRadiance[e] / referenceRadiance)
measured_ev  = nominal_ev + deviation_ev
```

`metrics.json` 同时给出每帧剪裁比例、压黑比例、可用比例和最大绝对偏差。

色彩按以下顺序处理，避免“先混合、后校色”造成色偏：

1. 直通 sRGB 帧解码到线性 RGB。
2. 用相机白平衡估计或元数据得到 RGB 增益。
3. 在线性空间把增益应用到虚拟球体。
4. 在线性空间按深度可见 alpha 混合直通和虚拟物体。
5. 色调映射到 sRGB。
6. 最后把半透明系统 UI 以 display-sRGB alpha 叠到画面最上层。

系统层不参与场景深度测试，它是显示空间的 UI 覆盖层；其覆盖率、平均 alpha 和混合顺序写入指标。

## 指标

- `passthrough_latency`：从帧可用（`CaptureBundle.CapturedAt`）到合成完成的墙钟时间，统计 min/mean/p95/max 和预算内帧数。合成测试夹具的生成不计入该延迟，避免把离线生成场景误当成相机传输延迟。
- `depth`：总无效深度比例、球体覆盖区的可见/遮挡/无效比例及置信度均值。
- `exposure`：每档曝光的标称 EV、测量 EV、相对偏差、剪裁和可用像素比例。
- `color_alignment`：白平衡方法、RGB 增益、混合空间，以及“是否先校色再混合”。
- `system_layer`：半透明 UI 的覆盖率、平均 alpha 与混合顺序。

置信度图综合了深度有效性、深度边缘和曝光融合权重；无效深度权重为 0，深度跳变边缘会降权。它只表示像素可信程度，不改变真实立柱的几何遮挡。

## 代码结构

- `scene.go`：解析场景、参考深度、无效深度区、系统层和三档曝光输入。
- `camera.go`：sRGB/线性转换、曝光融合、白平衡和曝光偏差测量。
- `compose.go`：球体求交与着色、深度可见性、置信度和合成。
- `report.go` / `output.go`：指标汇总与 PNG/JSON 写出。
- `pipeline_test.go`：覆盖深度遮挡、无效深度拒绘、曝光偏差、先校色后混合、延迟统计和输出文件。
