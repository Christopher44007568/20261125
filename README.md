# Hand late composition under world-frame lag

Go 标准库实现的对比仿真：世界帧（环境几何/相机位姿）以 30 Hz、100 ms 延迟到达，
手部追踪以约 120 Hz、15 ms 延迟到达，显示以约 60 Hz 合成。相机和控制器都在持续
运动，控制器不固定在世界原点。

## 三条合成路径

- `world-sync`：手和相机只消费同一版已到达世界帧里的配对样本，新的手样本必须等下一次
  世界更新。表现为整体滞后约 120 ms。
- `late-compose`：用最新世界帧提供的相机/遮挡几何做独立合成，手部直接取最新 120 Hz 样本；
  追踪丢失时用最后两帧线速度做航位推算，超过 200 ms 自动退化为冻结，避免发散。
- `freeze`：追踪正常时与 late-compose 一致；一旦丢失，保持最后一个有效姿态不做外推。

## 深度与图层

- 遮挡判定走保守射线-AABB 测试（`internal/camera`），手部点相对遮挡面保留 1 cm 深度偏置，
  因此不会用过期深度把手画到前景面板前面。
- 指标区分两类图层错误：`through`（真值在面板后却被画出，即穿前景）和 `over-hide`
  （真值在面板前却被旧几何隐藏）。

## 场景与指标

- `wave`：快速横挥并扫过前景面板，考察轨迹与图层。
- `grab`：接近、捏合、抬起再松开，考察 pinch 接触误差。
- `loss`：1800–2400 ms 追踪丢失，单独统计丢失窗口 RMSE。

指标含轨迹 RMSE/P95、pinch RMSE、接触 RMSE、穿模次数、误遮挡比例、手/世界帧龄期，
结果写入 `artifacts/metrics.csv`，每场景另出三策略同屏帧和俯视轨迹 PNG。

## 运行

```
go run ./cmd/handlate
```

仅依赖 Go 标准库；PNG 编码、点阵字体和绘图原语均在 `internal/render` 内实现。
