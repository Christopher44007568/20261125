# Groom 中间姿态插值（Go 标准库）

两套发丝数量不同的 groom 在中间姿态下插值。根部在确定性的 Hilbert scalp atlas 上排序，再按分位重采样到中间帧的发丝数量；只混合 atlas 中相邻发丝，不使用随机索引配对。输出包含 Groom A、Groom B、混合结果的正面/侧面/顶面三视图，以及控制点 A→B 迁移热色。

## 运行

```sh
go test ./...
go run . -out artifacts
```

也可直接打开 `artifacts/report.html`。生成过程不需要浏览器、图像库、字体包或网络，依赖只有 Go 标准库。

## 输出

- `artifacts/<scenario>/three_view.svg`：3 行（A、B、Blend t=0.50）× 3 列（正面、侧面、顶面）。
- `artifacts/<scenario>/control_migration.svg`：混合结果的控制点迁移细节，抽样虚线箭头展示 A→B 轨迹。
- `artifacts/<scenario>/motion_sheet.svg`：t=0、0.25、0.50、0.75、1.00 的中间帧，含尖端包络数值。
- `artifacts/metrics.json`：33 个验收帧的完整指标和确定性摘要。
- `artifacts/report.html`：汇总报告与所有 SVG 入口。

场景：

| ID | Groom A | Groom B | 中间帧数量 |
|---|---|---|---:|
| `curly_to_straight` | 卷发，63 根 | 直发，87 根 | 75 根 |
| `long_to_short` | 长发，69 根 | 短发，99 根 | 84 根 |

## 方法

1. 两套 groom 都有 13 个控制点。根部局部坐标先映射到半球 Hilbert atlas；相同 atlas 顺序保证两套 groom 的对应关系是空间连续的。
2. 中间帧发丝数量为 `K=round((1-t)nA+tnB)`。把 `u=j/(K-1)` 映射到各 groom 的 atlas 排名，在相邻两根发丝间线性重采样。数量不同也不会出现随机配对。
3. 角度用最短角差插值，两套 groom 的局部发丝在各自头皮坐标系完成对应，再统一施加中间姿态。
4. 每个混合控制点是两个对应源控制点的凸组合。因此控制点相对根部的距离、分段长度与尖端半径都不会超过两端对应量的线性包络；这是“中间帧不发散尖端”的算法保证，而非渲染后裁剪。
5. 颜色由蓝→青→黄→橙→红表示控制点从 A 到 B 的迁移量，单位 mm（`1 世界单位 = 200 mm`）。三视图的发丝本身和迁移细节图中的控制点圆点使用同一标尺。

## 验收

`go test ./...` 检查：

- 两套场景发丝数量不同，卷发/直发与长发/短发的几何差异成立。
- t=0 与 t=1 精确复现 Groom A/B，包括宽度、控制点和姿态。
- 每次运行得到相同确定性摘要；没有使用 `math/rand`。
- 每根输出发丝都有有效的 A/B atlas 参考，权重和为 1。
- 以 1/128 步长扫描全部中间帧：尖端、控制点和分段相对源发丝包络的越界量均不超过 `1e-8`。
- 生成的三张 SVG 可解析、无 NaN/Inf；完整运行生成报告、JSON 和所有场景文件。

当前两项场景的最大尖端越界、控制点越界和分段越界均为 `0`。
